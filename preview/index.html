4Korean PII Replacement Benchmark

한국어 요약 같은 개인정보 위치를 가리고 가리는 방식만 바꿔 LLM에 같은 질문을 던졌습니다. 별표(***)는 0점, 뜻 없는 코드는 문서 76.7점, [전화번호_A]처럼 종류를 남긴 표식은 문서 99.3점이었습니다(원문 98.0점). 종류를 남기고 복원하는 이 방식은 LLM Capsule이 쓰는 치환 방식입니다. 정답 위치를 미리 준 통제 실험이라 특정 제품의 전체 성능은 아닙니다.

Korean PII Replacement Benchmark measures how the form of PII replacement affects what an LLM can still answer from masked Korean text. … A typed, entity-indexed token such as [전화번호_A] stays at the level of the unmasked text. This typed, entity-indexed replacement with local restoration is the approach used in LLM Capsule.

8톡방에서 누르면 보이는 화면

위쪽 회색 띠(Spaces, 좋아요, Running)는 허깅페이스가 붙이는 틀이고, 그 아래가 우리가 만든 space-index.html입니다.

읽는 순서

한 줄 결론 → 전화번호 하나가 방식별로 어떻게 바뀌는지와 점수(원문 기준선 → 종류 표식 → 뜻 없는 코드 → 별표) → 과제와 조건 설명 → 버튼 세 개. 순위(Rank)는 넣지 않았습니다. 조건 3개로 우리 방식을 1위에 올리면 비교 실험보다 홍보표로 읽히기 때문입니다. 한국어는 오른쪽 위 「한국어」로 넘어가는 별도 페이지입니다.

탭

Detailed results는 두 과제 전체 점수와 신뢰구간, Method는 방식 설명과 한계, Data는 원본 출처, Citation은 인용 형식입니다. 기술 질문이 오면 이 탭을 가리키면 됩니다.

LLM Capsule 연결

첫 문장(「LLM Capsule replaces it with a typed token…」), 표의 「LLM Capsule method」 줄, 버튼 「Evaluate your own masking tool」(데모 신청)과 「See how LLM Capsule applies it」(비교 자료), 맨 아래 "Built by CUBIG"입니다. v0.1에서는 데모 버튼을 데이터셋 페이지 ⑥에만 뒀는데, 톡방에서 들어온 사람이 다음으로 갈 곳이 없어 v0.2에서 결과 페이지에도 넣었습니다. 문구는 영업 대신 「내 도구로 평가해 보기」로 썼습니다.
